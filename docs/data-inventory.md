# Data inventory

The single list of what Recipes stores and sends, for the privacy policy (owner's legal-text generator), Apple's
privacy labels and Google's Data safety form (plan 4.9, AC44). Generated by hand from the code on 2026-11-25 and kept
in step by `tools/guards.ts` (check `data-inventory`): every table and meta key in `backend/src/storage/migrations.ts`
and `backend/src/user-do.ts`, and every metric event in `backend/src/metrics.ts`, must appear here in backticks.

Engineering facts, not legal advice. "User" means one account: one Durable Object named by the user id, which is
HMAC-SHA256 of the provider's subject under the secret `USER_ID_PEPPER`. No name, no email address, no phone number
and no device identifier is stored by the backend.

## Where it lives

All per-user data lives in that user's Durable Object (SQLite), in Cloudflare's EU jurisdiction
(`DO_JURISDICTION = "eu"`, `backend/wrangler.jsonc`), encrypted at rest by Cloudflare. Cloudflare's point-in-time
recovery can restore an object to any point in the last 30 days, also after erasure (`docs/runbooks/restore.md`
forbids restoring an erased object).

## Tables of the user object

| Table | Content | Purpose | Retention (as implemented) |
|-------|---------|---------|----------------------------|
| `meta` | key/value settings, see below | account state and counters | until erasure; tombstone keys 12 months after it |
| `tasks` | scheduled work: job runs, timeouts, expiry, entitlement refresh, Apple code exchange, deletion, tombstone wipe | alarms | until run; `tombstone_expiry` 12 months (`TOMBSTONE_TTL_MS`, `user-do.ts`) |
| `sessions` | SHA-256 of the session secret, created and expiry time, provider name | sign-in | 30 days from last daily extension (`SESSION_TTL_MS`, `user-do.ts`); at most 10 (`MAX_SESSIONS`); all removed when deletion starts |
| `used_nonces` | random nonce id and its expiry | single use of sign-in nonces | 5 minutes (`NONCE_TTL_MS`, `auth/nonce.ts`), purged by the expiry task |
| `recipes` | recipe JSON (title, text, ingredients, steps, tags, source URL, language), revision, deletion marker | the service itself | until the user deletes it; deletion markers 90 days (`MARKER_TTL_MS`, `user-do.ts`) |
| `images` | picture bytes, type, size, share-check result | the service itself | until removed from the recipe or the recipe is deleted |
| `translations` | translated recipe JSON per language | Pro feature | with its recipe |
| `daily_counters` | requests per day and route group; PDF and picture-check counts | limits, admin page | 90 days (`COUNTER_DAYS`, `user-do.ts`) |
| `jobs` | AI job kind, status, input (URL, text or photo) while running, draft result, charge | AI import and translation | input deleted when the job ends; the row 7 days (`JOB_RESULT_DAYS`, `user-do.ts`) |
| `usage` | monthly AI units used | quota | until erasure |
| `attempts` | failed AI attempts per day | abuse limit | 1 day (`expire()` in `user-do.ts`) |
| `reports` | the user's own reports: kind, job or share id, reason, free-text note | content moderation (Google Play AI-content policy) | 90 days (`REPORT_DAYS`, `user-do.ts`) |
| `shares` | share id, recipe id, creation and expiry, revoked flag | sharing by link | 30 days (`SHARE_TTL_MS`, `share.ts`) |
| `share_accepts` | share id and SHA-256 of each recipient's user id | at most 10 recipients | with the share |
| `audit` | time, operator email (Cloudflare Access identity), action, reason code | admin actions on this account | until erasure (accepted: the audit goes with the account; a suspension itself survives in the tombstone) |

## Meta keys

| Key | Content | Retention |
|-----|---------|-----------|
| `schema_version` | storage version | until erasure |
| `state` | `active`, `suspended`, `deleting` or `tombstone` | kept in the tombstone |
| `suspension_reason` | reason code | while suspended; kept in the tombstone, so deleting and returning does not lift a suspension |
| `metrics_id` | random UUID used as the metrics index | until erasure; a returning account gets a new one |
| `created_at` | account creation time | until erasure |
| `rev`, `purged_rev`, `recipe_bytes` | sync cursor, purge horizon, stored text size | until erasure |
| `consent_version` | accepted AI notice version | until withdrawn or erasure |
| `free_import_used_at` | when the free import was used | kept in the tombstone (abuse prevention) |
| `free_import_refunds` | count of refunded free imports | kept in the tombstone |
| `tombstone_until` | end of the tombstone | 12 months (`TOMBSTONE_TTL_MS`) |
| `entitlement` | subscription state from RevenueCat: active, expiry, grace end, product id | until erasure |
| `entitlement_at`, `entitlement_tried_at`, `entitlement_failed_at`, `entitlement_client_at` | refresh times | until erasure |
| `apple_auth_codes` | Sign in with Apple authorization codes, one per client id (app bundle id, web Services ID), until exchanged | at most 5 minutes (`APPLE_CODE_TTL_MS`, `user-do.ts`) |
| `apple_refresh_tokens` | Apple refresh tokens, one per client id, kept only to revoke each at deletion | until erasure (each revoked first) |
| `month_usage` | only in a tombstone: this month's AI unit count `{ period, count }`, restored at the next sign-in | 12 months with the tombstone; used only within its month |
| `deletion_started_at`, `deletion_done_revenuecat`, `deletion_done_apple` | deletion progress (key pattern `deletion_done_<step>`) | until erasure |
| `local_entitlement` | local development switch only (`src/testing/local-billing.ts`, never in production) | local only |

## Tombstone

The tombstone is pseudonymous personal data: it lives in the object named by the user id, which is derived from the
provider's subject (HMAC with `USER_ID_PEPPER`), so the same Apple or Google account reaches it again. It holds only
`state`, `tombstone_until`, and where they apply `free_import_used_at`, `free_import_refunds`, `suspension_reason` and
`month_usage` (`TOMBSTONE_KEYS`, `user-do.ts`), for 12 months (`TOMBSTONE_TTL_MS`). Purpose: preventing repeated free
imports, escaping a suspension and resetting the monthly AI quota by deleting and signing in again. It is written only
when one of these facts exists; otherwise the object is emptied completely (`deleteAll()`). Nothing about recipes,
pictures, sessions, the subscription or the provider identity is kept. The admin audit rows are not kept (accepted: the
operator's record of a suspension is its reason code in the tombstone).

Third-party deletion steps (RevenueCat customer, Apple token revocation) are retried for at most 7 days
(`THIRD_PARTY_DEADLINE_MS`, `user-do.ts`); after that the erasure runs anyway and a metric names the abandoned step.

## Metric events (Workers Analytics Engine)

Retention: three months (Cloudflare,
https://developers.cloudflare.com/analytics/analytics-engine/limits/). No content and no user id. Events about a user
carry the random `metrics_id` as index; it is destroyed at erasure, so old rows can no longer be tied to anyone.

| Event | Fields (blobs) | Written by |
|-------|----------------|------------|
| `account_created` | none | user object |
| `session_created` | none | user object |
| `request` | route group, HTTP status (job polling not counted) | user object |
| `import_outcome` | job kind, outcome; duration | user object |
| `quota_denied` | reason code | user object |
| `report` | kind, reason code | user object |
| `entitlement_refresh` | trigger, outcome | user object |
| `share` | outcome code | user object |
| `pdf` | outcome code | user object |
| `screen` | outcome code | user object |
| `account_deletion` | started, step_retry, erased (user object, before erasure); third_party_abandoned with the step name (Worker side, no index) | user object, or no index |
| `admin_action` | suspend or unsuspend, reason code | user object |
| `auth_failure` | reason code | Worker, no index |
| `rate_limited` | route name | Worker, no index |
| `provider_unavailable` | provider name | Worker, no index |
| `billing_webhook` | RevenueCat event type | Worker, no index |
| `share_report` | reason code, encrypted reference to the reported account (opens for 30 days, `REPORT_REFERENCE_TTL_MS`, `share.ts`) | Worker, no index |
| `internal_error` | reason code (for example `erase_refused`) | Worker, no index |
| `entitlement_mismatch` | trigger | Worker, no index |

## Logs

Workers Logs keep only the Worker's own console lines (event names and status codes), no request URLs
(`observability` in `backend/wrangler.jsonc`). Retention is set by Cloudflare's Workers Logs product (UNVERIFIED here;
check the plan's current value when the owner logs in).

## Processors

| Processor | Receives | Where | Retention |
|-----------|----------|-------|-----------|
| Cloudflare (Workers, Durable Objects, Workers AI, AI Gateway, Analytics Engine, Turnstile, Access, Browser Run) | everything above; AI inputs (recipe page text, photo or text, recipe for translation, pictures at share time) for the model call only, with gateway payload logging and caching off; Turnstile sees the visitor's IP; Access sees the operator's identity | storage in the EU; Workers AI processing not guaranteed in the EU | as in the tables above; AI inputs not kept by Workers AI for plain inference (Cloudflare's data-usage page) |
| RevenueCat (US) | the user id as app user id; the store SDK in the app also sends device and purchase data | US, with SCCs | RevenueCat's own; the customer is deleted at account deletion (`deleteCustomer`, `billing/revenuecat.ts`) |
| Apple | Sign in with Apple: the id token and authorization code come from Apple; the backend sends the code back for a refresh token and revokes it at deletion | Apple | Apple's own; token revoked at deletion (`auth/apple.ts`) |
| Google | Sign in with Google: the id token comes from Google; the backend only fetches Google's public keys | Google | Google's own |

## Retention summary

| Period | What | Constant |
|--------|------|----------|
| 5 minutes | sign-in nonces, Apple authorization codes | `NONCE_TTL_MS` (`auth/nonce.ts`), `APPLE_CODE_TTL_MS` (`user-do.ts`) |
| 1 day | failed-attempt counts | `expire()` in `user-do.ts` |
| 7 days | finished AI jobs | `JOB_RESULT_DAYS` (`user-do.ts`) |
| 30 days | sessions after last use, share links, report references, point-in-time recovery | `SESSION_TTL_MS` (`user-do.ts`), `SHARE_TTL_MS`, `REPORT_REFERENCE_TTL_MS` (`share.ts`), Cloudflare |
| 90 days | deletion markers, daily counters, own reports | `MARKER_TTL_MS`, `COUNTER_DAYS`, `REPORT_DAYS` (`user-do.ts`) |
| 3 months | metric events | Cloudflare Analytics Engine |
| 7 days | longest wait for a third-party deletion step | `THIRD_PARTY_DEADLINE_MS` (`user-do.ts`) |
| 12 months | tombstone after erasure (pseudonymous, see "Tombstone") | `TOMBSTONE_TTL_MS` (`user-do.ts`) |
| until the user deletes it or the account | recipes, pictures, translations, usage, audit, entitlement | erasure (plan 4.7) |
