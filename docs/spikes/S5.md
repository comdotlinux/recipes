# S5: commonTest UI tests and Roborazzi as Android host tests on Linux

Date: 2026-11-24. Host: Linux x86_64, no emulator, no Mac. JDK Temurin 25.0.5.1 (from `mise.toml`), Gradle 9.7.0, AGP 9.3.1, Kotlin 2.4.21, Compose Multiplatform 1.12.2, Robolectric 4.18.1, Roborazzi 1.79.0.

## Question

Can a Compose UI test written once in `commonTest` with `runComposeUiTest` run as an Android host test (JVM with Robolectric, no emulator) on Linux, and can a Roborazzi screenshot test run and verify the same way?

## Result: PASS. The plan's alternative (a `jvm` target for tests) is not needed.

## How it works

- `shared` uses `com.android.kotlin.multiplatform.library` with `withHostTest { isIncludeAndroidResources = true }`. The `androidHostTest` compilation includes `commonTest`, so common tests run on the JVM.
- A test in `commonTest` has no JUnit runner annotation, and without Robolectric the Android framework is not available. The fix is one `expect abstract class UiTest()` in `commonTest`:
  - `androidHostTest` actual: annotated `@RunWith(RobolectricTestRunner::class)`, `@GraphicsMode(GraphicsMode.Mode.NATIVE)`, `@Config(sdk = [36], qualifiers = "w360dp-h640dp-xhdpi")`. `@RunWith` is `@Inherited`, so every common subclass runs under Robolectric.
  - `iosTest` actual: an empty class.
- The common UI test is `shared/src/commonTest/kotlin/app/recipebox/AppUiTest.kt` (`AppUiTest : UiTest()`), using `androidx.compose.ui.test.v2.runComposeUiTest` (the v1 function is deprecated in Compose 1.12).
- `androidx.compose.ui:ui-test-manifest` in `androidHostTest` gives Robolectric the `ComponentActivity` that `runComposeUiTest` starts.
- The screenshot test is `shared/src/androidHostTest/kotlin/app/recipebox/AppScreenshotTest.kt`. It uses the same `runComposeUiTest` and `onRoot().captureRoboImage(...)`. Roborazzi is Android/JVM only here, so it lives in `androidHostTest`, not `commonTest`.
- Baselines are committed in `shared/src/androidHostTest/screenshots/` (`app_light.png`, `app_dark.png`, 720 x 1280). `roborazzi.test.verify=true` in `gradle.properties` makes the normal test task compare against them, so `check` verifies screenshots.

## Notes and limits

- JDK 25 prints `WARNING: java.lang.System::load has been called by org.robolectric.nativeruntime.DefaultNativeRuntimeLoader`; it is a warning only.
- Screenshot pixels depend on Robolectric's native graphics for the host OS. Baselines were recorded on Linux x86_64; CI must verify on Linux, not on the macOS runner.
- On Linux, `commonTest` is also compiled for iOS (`:shared:compileTestKotlinIosSimulatorArm64` runs), but linking and running it (`:shared:iosSimulatorArm64Test`) is SKIPPED: "simulator tests require macOS". Whether `runComposeUiTest` passes on the iOS simulator is checked on the macOS CI runner.
