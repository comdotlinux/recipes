# S4: iOS seams from Kotlin/Native without Swift

Date: 2026-11-24. Status: **compiled on Linux; result pending the macOS CI job.** The tests cannot run on this Linux host (`:shared:iosSimulatorArm64Test` is skipped: "simulator tests require macOS").

## Question

Can the three iOS platform seams be written in Kotlin/Native, with no Swift beyond the app entry point (budget 60 lines, AC3)?

- `SecureStore` on the Keychain
- `TurnstileView` on `WKWebView`, with a JavaScript-to-Kotlin bridge that delivers the Turnstile token
- `AuthProvider` with Sign in with Apple (`ASAuthorizationAppleIDProvider`), no scopes, nonce set

Pass condition (plan section 6): CI simulator tests pass for a Keychain round trip, a `WKWebView` bridge message and Apple request construction. Real sign-in is a manual check on a device.

## Implementation (all Kotlin, `shared/src/iosMain/kotlin/com/linux/recipes/platform/`)

| File | What it does |
|------|--------------|
| `KeychainSecureStore.kt` | Generic-password items (`kSecClassGenericPassword`, service = bundle id, account = key) through `SecItemAdd`, `SecItemCopyMatching`, `SecItemDelete` with CoreFoundation dictionaries. Accessibility `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, so the token is excluded from backups and device transfer. |
| `TurnstileView.ios.kt` | `UIKitView` around a `WKWebView`. The page posts the token to the script message handler `turnstile` (docs/api.md, "Turnstile page"); the handler accepts messages only from the base URL's host. A `WKNavigationDelegate` cancels every navigation that `TurnstilePolicy.isAllowed` rejects (the base URL's own origin and `https://challenges.cloudflare.com`) and reports an HTTP error of the page itself, such as 503 `not_configured`, through `onError`. |
| `AppleAuthProvider.kt` | `ASAuthorizationController` with one `ASAuthorizationAppleIDRequest`: `requestedScopes` empty (no name, no email), `nonce` = SHA-256 hex of the server nonce, as `docs/api.md` requires for Apple. The delegate and presentation anchor are Kotlin `NSObject` subclasses. Cancel maps to `AuthResult.Cancelled`. |
| `Sha256.ios.kt` | `actual` of the common `sha256Hex` with `CC_SHA256` from CommonCrypto; the common test `Sha256Test` checks FIPS 180-2 vectors on Android and iOS. |

Swift stays at the 19-line entry point in `iosApp/iosApp/iOSApp.swift`; no Swift shim was needed.

## Known risks the CI run decides

- Kotlin/Native simulator tests run as a plain executable inside the simulator, not as an app with entitlements. If `SecItemAdd` returns `errSecMissingEntitlement` (-34018) there, the Keychain test fails for that reason only, and the round trip has to be checked from the app (manual check or an XCTest host) instead.
- `WKWebView` needs its web content process. If that process does not start for a plain test executable, the bridge test times out after 30 s; the same check then moves into the app on a device.
- Sign in with Apple also needs the `com.apple.developer.applesignin` entitlement and a team. That is not in `iosApp` yet, because the CI build runs unsigned for the simulator. It is added with the signing setup (spike S6).

## If it fails

The plan's alternative is a thin Swift shim behind the same interfaces, within the AC3 budget of 150 lines.

## Reinstall starts signed out

Keychain items survive deleting the app. `AppGraph.clearStaleTokenOnFirstLaunch` removes the stored token when the marker file `<filesDir>/installed` is missing and then writes it; app files do not survive deletion, so the first launch after a reinstall starts signed out. The logic is tested in common code (`SessionRepositoryTest.firstLaunchAfterInstallStartsSignedOutLaterLaunchesKeepTheSession`). Only a device can prove the premise itself: install, sign in, delete the app, reinstall, and see the sign-in screen.
